# 04 Test, Verify, Refine

Status: ready
Time: 14:00–14:45 (45 min) · Talk 12 / do 33
Outcomes: LO5 (LO1 reinforced)

## Purpose

Replace "try again until it looks better" with a deliberate method: decide what
good means first, change one thing at a time, and verify the result by hand
before trusting it.

## By the end of this block, participants can…

- Write pass/fail criteria for an output before running the prompt
- Improve a prompt one change at a time and record what helped
- Apply the verification checklist to an output, including fairness and plain
  language

## Talking points (9 min)

1. **Criteria first.** Write down three to five pass/fail checks before you run
   it. Otherwise you'll judge by fluency, and AI is always fluent.
2. **One change at a time.** If you change five things and it improves, you
   don't know which one helped, and you can't reuse the lesson.
3. **Results vary.** Same prompt, different answers (they saw it in the 03
   warm-up). For anything you'll reuse, run it twice. A change that helps once
   might be luck.
4. **The verification checklist.** Walk through
   [verify-checklist.md](../../handouts/verify-checklist.md): numbers, names,
   citations, "must" statements, omissions. Then read it as the audience:
   plain language, fairness, accessibility, promises.
5. **Fairness is a criterion, not a feeling.** For public-facing work, check
   whether it describes groups differently, assumes things about readers, or
   would read differently to different residents. Put it on the criteria list.
6. **Self-check is useful, not sufficient.** "Check your answer against the
   source and list anything unsupported" catches some errors. It's the same
   tool grading its own work, so it doesn't replace you.

## Check for understanding

Look at iteration logs while circulating. A good log has one change per row,
and its scores go up *and sometimes down*. A log with "made it better" in
every row means they're changing several things at once.

## Common problems

| Problem | Response |
| --- | --- |
| Criteria are vague ("clear", "professional") | "How would two people check that and agree?" Push to something countable |
| Participant keeps editing in the same chat | Fine for small fixes; for the log, a new chat per round keeps rounds comparable |
| First version already passes everything | Raise the bar: add a criterion for the actual audience (one page? council-ready?) |
